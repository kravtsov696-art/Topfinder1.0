# KNOWN_LIMITATIONS — ограничения и расхождения

## Платформенные (не обходятся кодом)

1. **ОС решает, когда присылать точки.** Никакой фиксированной частоты. В ECO при неподвижном телефоне точек может не быть десятки минут — карта честно покажет «устаревшая/историческая», а не «здесь сейчас». Отдельно показывается «телефон выходил на связь».
2. **iPhone, «смахнутое» приложение.** Стандартные обновления останавливаются. expo-location дополнительно включает significant-change monitoring (в нативном коде `EXLocationTaskConsumer.m`), который может перезапустить приложение при заметном перемещении (порядка сотен метров) — проверяется сценарием 4a; не обещаем.
3. **Android 12+: foreground service нельзя запустить из фона.** Поэтому режимы включаются только из открытого приложения. После перезагрузки фоновые обновления, вероятно, не возобновятся до открытия приложения (сценарий 5 это измерит). Оболочки Xiaomi/Huawei/Samsung могут убивать сервис — это предмет испытаний, без скрытых обходов.
4. **Android без foreground service** (переключатель «ECO без уведомления») получает фоновые точки лишь несколько раз в час — для сравнения.
5. **Запрос обновления в фоне без push** доходит только если ОС сама разбудила приложение новой точкой (канал `fix_response`). Иначе — `timeout`, это штатный исход.
6. **Геозоны**: системные события запаздывают (минуты), радиус < 100 м ненадёжен; событие пишется как «системное», не как подтверждённый вход.
7. **Точность в помещении** может быть сотни метров; приложение не делает выводов об этаже/комнате.

## Этап D: исследование (без реализации)

### iOS Location Push Service Extension (LPSE)
По официальной документации Apple (на момент моих знаний — июнь 2026; ссылку проверить перед реализацией):
- нужен **отдельный entitlement** `com.apple.developer.location.push`, который Apple выдаёт **по заявке** (форма запроса, обоснование «явно одобренный обмен местоположением»);
- платный Apple Developer Program; отдельный target-расширение `CLLocationPushServiceExtension`; авторизация **«Всегда»**;
- отдельный APNs-токен (`CLLocationManager.startMonitoringLocationPushes`), push с `apns-push-type: location`, topic `<bundleId>.location-query`; доставка в расширение даже без запущенного приложения, но с системными квотами;
- Expo не поддерживает это «из коробки» → нужен свой config plugin + Swift-target.
**Блокеры сейчас:** нет entitlement, нет Apple-аккаунта в этой среде. **Fallback:** опрос при открытом приложении + `fix_response` в фоне (уже работают), затем обычный silent push (этап D-1).

### Android: FCM + геолокация в фоне
- Высокоприоритетное FCM-сообщение — одно из исключений, позволяющих запустить foreground service из фона; но для FGS типа `location`, запущенного из фона, доступ к геолокации требует уже выданного `ACCESS_BACKGROUND_LOCATION` (ограничения «while-in-use»). Если FGS ECO уже работает, push не нужен — достаточно сервиса, который читает запросы при очередной точке.
- Частые high-priority сообщения без видимого результата система может понижать в приоритете → «push ≠ право разбудить».
- Для Expo push на Android нужен Firebase-проект (`google-services.json`) и FCM v1 ключ, загруженный в Expo.

### Что нужно для этапа D-1 (silent push на обеих платформах)
1. Apple Developer Program + APNs Key (`.p8`) — загрузить в Expo; 2. Firebase-проект (`google-services.json`) — в репозиторий **не коммитить**, передать как секрет CI; 3. включить в `app.config.ts` плагин `expo-notifications` и фоновую задачу; 4. на сервере `PUSH_PROVIDER=expo`. Серверная часть и статусы (`push_sent` ≠ `device_received`) уже готовы.

## Расхождения с исходной спецификацией

| Спецификация | Сделано | Причина |
|---|---|---|
| Fastify/NestJS | `node:http` + маленький роутер | ADR-API-1 в ARCHITECTURE.md |
| Нативные Swift/Kotlin-адаптеры (блупринт §7.2–7.3) | expo-location/TaskManager | ТЗ P0 допускает Expo Location для первой реализации; нативные модули — когда измерения покажут нехватку |
| Режимы MOVING/ON_DEMAND/LOW_POWER/SOS | не отдельные режимы | P0: OFF/ECO/ACTIVE_TRIP по ТЗ; ON_DEMAND = запрос обновления |
| QR-код приглашения | только 8-символьный код | ТЗ: «код или QR»; QR добавить вместе с камерой в P1 |
| Expo Development Build | release-сборка с вшитым JS (не Expo Go, свой нативный код) | телефонам не нужен компьютер с Metro рядом |
