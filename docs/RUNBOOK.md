# RUNBOOK: от кода до двух телефонов

Порядок: **1) код на GitHub → 2) сервер с HTTPS → 3) APK на Android → 4) сборка на iPhone → 5) первый обмен → 6) выгрузка результатов.**

---

## 1. Код на GitHub

Нужен GitHub-аккаунт и **приватный** репозиторий (например, `blizkie`). Два способа:
- **Проще всего:** подключить GitHub к Claude (claude.ai → Settings → Connectors → GitHub) и сказать «залей проект в репозиторий X» — я отправлю код и запущу сборки сам.
- Вручную: на github.com → New repository → «uploading an existing file» → перетащить содержимое архива.

После первой отправки откройте вкладку **Actions**: должен пройти workflow `ci` (тесты сервера, проверка мобильного кода, prebuild). Он же сохранит `package-lock.json`.

## 2. Сервер (нужен публичный HTTPS-адрес)

Телефоны ходят на сервер через сотовую сеть, поэтому нужен адрес `https://…`. Варианты:

### Вариант A — свой VPS (рекомендую для замеров)
Любой VPS с Ubuntu 22.04/24.04, 1 ГБ RAM (оплата в рублях у российских хостеров подходит). Открытые порты 80 и 443.
```bash
ssh root@IP_СЕРВЕРА
git clone https://github.com/<вы>/blizkie.git /opt/blizkie     # для приватного репо — с токеном или deploy-key
cd /opt/blizkie/deploy/vps && bash install.sh
```
Скрипт поставит Docker, создаст `.env` (пароль БД, `ADMIN_TOKEN`), поднимет PostgreSQL+PostGIS, API и Caddy с бесплатным сертификатом на адрес вида `https://203.0.113.10.sslip.io`, и в конце напечатает адрес. Проверка с компьютера: открыть `https://…/health` → `{"ok":true,…}`.

Смоук-тест удалённого сервера (с любого компьютера с Node 22.18+): `node apps/api/test/smoke.ts https://ваш-адрес`.

### Вариант B — Render (бесплатно, но с оговорками)
render.com → New → Blueprint → выбрать репозиторий (файл `render.yaml`). Минусы бесплатного плана: сервис **засыпает после 15 мин без запросов** (первый запрос 30–60 с), база удаляется через 30 дней. Для испытаний фона это искажает задержки — отмечайте в матрице.

### Локально (для разработчика)
`docker compose up --build` → `http://localhost:8080/health`. Телефоны на http не пойдут (iOS ATS / Android cleartext), нужен HTTPS-туннель или вариант A.

## 3. Android: установка APK

1. GitHub → Actions → **android-apk** → Run workflow → в поле «Адрес сервера» вставить `https://…` → Run. (~15 мин)
2. Готовый файл: GitHub → Releases → **p0-android** → `blizkie-p0-N.apk` (откройте страницу на самом телефоне, войдя в GitHub) или Actions → запуск → Artifacts.
3. На телефоне: открыть APK → разрешить установку из этого источника → установить.
4. Это тестовая сборка, подписанная debug-ключом: не для Google Play. При обновлении поверх старой версии подпись совпадает, если собирали тем же workflow.

## 4. iPhone

Установить своё приложение на iPhone без подписи Apple невозможно. Есть два реальных пути:

### Путь 1 — платный Apple Developer Program + TestFlight (без Mac)
Что нужно от вас (пароли в чат не присылать):
1. Членство Apple Developer Program (99 $/год) на ваш Apple ID.
2. Ключ App Store Connect API: App Store Connect → Users and Access → Integrations → App Store Connect API → «+», роль **App Manager** → скачать `.p8`, записать **Key ID** и **Issuer ID**. Team ID — на developer.apple.com → Membership.
3. Аккаунт на expo.dev → Create project `blizkie-p0` → скопировать Project ID; Access tokens → создать токен.
4. В GitHub-репозитории → Settings → Secrets and variables → Actions:
   - Secrets: `EXPO_TOKEN`, `ASC_API_KEY_P8` (содержимое файла .p8), `ASC_KEY_ID`, `ASC_ISSUER_ID`, `APPLE_TEAM_ID`
   - Variables: `EAS_PROJECT_ID`, `API_URL` (адрес сервера)
5. В App Store Connect создать приложение (My Apps → «+» → New App) с Bundle ID `app.blizkie.p0` (если ID не в списке — сначала запустить шаг 6, EAS зарегистрирует его, затем создать приложение и повторить).
6. Actions → **ios** → Run workflow → `eas_build: production`. Сборка уйдёт в TestFlight. На iPhone поставить приложение **TestFlight** и установить «Blizkie P0».

> Этот путь я не прогонял: в моей среде нет вашего Apple-аккаунта. Первые ошибки подписи — нормальная часть настройки, пришлите текст ошибки.

### Путь 2 — Mac + Xcode + бесплатный Apple ID (7 дней)
Подходит для первого опыта, если есть Mac. Push не нужен (в этой сборке его нет), поэтому бесплатной подписи достаточно.
```bash
git clone https://github.com/<вы>/blizkie.git && cd blizkie && npm install
cd apps/mobile && EXPO_PUBLIC_API_URL=https://ваш-адрес npx expo prebuild -p ios
open ios/*.xcworkspace        # ожидается BlizkieP0.xcworkspace
```
В Xcode: Signing & Capabilities → Team = ваш Apple ID; Bundle Identifier сделать уникальным (например `app.blizkie.p0.ваше-имя`); подключить iPhone кабелем; на iPhone включить «Режим разработчика» (Настройки → Конфиденциальность → Режим разработчика); выбрать схему **Release** (Product → Scheme → Edit Scheme → Run → Build Configuration = Release, чтобы JS был внутри); Run. На iPhone: Настройки → Основные → VPN и управление устройством → доверять разработчику. Через 7 дней — пересобрать.

## 5. Первый обмен (≈10 минут)

На **обоих** телефонах:
1. Открыть приложение → вкладка **Моё** → адрес сервера → имя телефона → «Проверить сервер и зарегистрировать телефон».
2. «Разрешить геолокацию» → «При использовании» → затем «Всегда» (iPhone может спросить про «Всегда» позже — тогда Настройки → Blizkie P0 → Геопозиция → Всегда, **Точная геопозиция** вкл.). Android: «Разрешить в любом режиме», «Точное местоположение».

Связь:
3. Android → **Связь** → «Получить код». iPhone → **Связь** → ввести код → «Проверить код» → «Подтверждаю связь».
4. На обоих → «Включить обмен».
5. На обоих → **Моё** → «Измерить и отправить точку сейчас».
6. **Карта**: видно вторую точку, круг погрешности, возраст, статус. «Запросить обновление» → смотрите стадии.
7. Заблокируйте экран одного телефона, пройдите 200–300 м, смотрите на втором телефоне, обновляется ли точка и её возраст.

## 6. Выгрузка результатов

- С телефона: **Журнал** → «Журнал JSON» / «Отправки CSV» (локальные данные, включая не дошедшие точки) и «Сервер: …» → отправить себе (почта, мессенджер, Google Drive).
- Всё испытание сразу (на компьютере, с Node 22.18+): `API_URL=https://… ADMIN_TOKEN=… node scripts/summarize.ts` → папка `results/<дата>/` с CSV и `summary.md` (p50/p90 задержек, разрывы, успех запросов).
- Сначала выгружайте, потом удаляйте: точки на сервере живут 24 ч.

## Частые проблемы

| Симптом | Где смотреть | Что делать |
|---|---|---|
| «Нет связи с сервером» | Моё → последняя ошибка | открыть `https://…/health` в браузере телефона |
| Точки не идут при заблокированном экране | Моё → «Геолокация в фоне» | iPhone: «Всегда» + «Точная»; Android: «в любом режиме», отключить оптимизацию батареи для приложения |
| Android перестаёт слать после 5–30 мин | Журнал: нет `bg_locations` | Xiaomi/Samsung: «Автозапуск», «Без ограничений» в батарее; это и есть предмет испытания — запишите в матрицу |
| Запрос обновления — таймаут | шкала запроса: нет `device_received` | у второго телефона приложение в фоне, а ОС не присылала ему точек — ожидаемо до этапа D (push) |
